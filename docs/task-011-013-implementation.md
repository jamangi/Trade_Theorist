# Tasks 011–013: evaluation, dashboard and local operating interface

Implemented within the offline fixture scope. Real learning, vendor qualification,
forward evidence and owner-approved paper readiness retain their existing blockers.

`src/trade_theorist/evaluate/` replays portfolio-scoped ledger events on the declared
session schedule. It calculates net returns, drawdown, exposure, turnover, daily
volatility, worst session, round-trip hit rate and Brier calibration with reliability
bins. Cash and an independent index portfolio provide baselines. The immutable trial
registry includes failures and identifies matched mail/no-mail trials and separate
counterfactual capital. Review reports retain window/sample/contamination blockers;
only a recorded owner decision can mark qualified forward evidence reviewed.

`src/trade_theorist/export.py` creates strict versioned, hashed, allowlisted public
summaries and six linked answers. `schemas/dashboard-v1.json` is generated by
`scripts/export_dashboard_schema.py`. The dashboard consumes that same schema,
checks integrity, and reads only local export files. It has Council and Character
tabs, historical versions, experiment/advice/horizon filters, charts and exact table
alternatives, holdings, decision/governor results, considered mail, unresolved
objections, readiness, learning provenance, costs and evidence grades. It contains
no trade or model-call action.

`src/trade_theorist/operations.py` connects the existing ingestion, learning,
heartbeat, simulation and evaluation APIs. The earlier heartbeat fixture recipe
now lives in the installed package; its rebuild script remains compatible. A fresh
wheel installation can run `trade-theorist demo` from outside the source directory.
The demo seeds seven distinct trials: council, three sleeves, no-mail council,
index baseline and a risk-constrained counterfactual. It includes a discussion,
risk rejection, dividend, matured/pending forecast and deliberate missing Trend
session. Repeating it reuses completed work. Runtime provenance records the
executing Python source hash separately from historical fixture manifest specimens.

The [quickstart](quickstart.md) documents pinned Windows setup and a one-command
local preview; the [runbook](runbook.md) documents every implemented command and
its limits. The [hand calculations](../examples/evaluation/metric-checks.json)
explain the fixture arithmetic. No account, external model, vendor call, live
endpoint, recurring automation or deployment is involved in running the demo.

Validation includes hand arithmetic, fees/dividends counted once, stale marks,
unscorable/pending forecasts, late ingestion, historical cutoffs, baseline matching,
counterfactual separation, failed-trial retention, promotion exclusion, external-flow
rejection, schema/hash/privacy checks, atomic export interruption, CSV deduplication,
learning-plan resumption, heartbeat interruption/resumption and duplicate-free demo
replay. A fresh virtual environment installed the built wheel and pinned dependencies;
the isolated installed demo produced both dashboard views without source-path imports.
Final validation on 2026-09-06 passed all 134 tests across 16 isolated modules in
20.3 seconds. The generated dashboard schema, existing accepted contract bundle,
JavaScript syntax and whitespace checks also passed. A rebuilt final wheel was
reinstalled and its isolated demo repeated successfully in a fresh private fixture
root, reporting zero external model and network calls.

Browser walkthroughs exercised both tabs in nominal 1280px and 390px local test
frames (1272px and 382px content widths after scrollbars), with no page-level
horizontal overflow. The in-app viewport override did not resize its document, so
explicit local frames were used for reliable breakpoint checks. Keyboard checks
covered arrow-key tabs, Tab focus, saved-version selection, all six disclosures,
evidence dialogs and Escape. Empty filters, stale Trend, no-trade council, pending
outcomes and a missing-report recovery page were checked. Tables have their own
keyboard-focusable scrolling regions. Opening panels reads already loaded records.

No blocker remains for the bounded fixture deliverables. Broader real-provider
orchestration, forward trials and public hosting were not implicitly launched.
