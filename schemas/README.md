# Versioned contracts

Operational v2 contracts are separate in `contracts-v2.json`, generated by
`scripts/export_schemas_v2.py` or `trade-theorist export-v2-schema <output>`.
Explicit version dispatch and separate storage preserve v1 hashes and replay.
See [Step 01](../docs/step-01-contracts.md) for typed events, private attribution,
source-rights requirements and the synthetic preview/apply migration workflow.
[Step 02](../docs/step-02-accounting.md) adds frozen accounting/funding plans,
execution terms/receipts, operating costs, account reconciliation and private
performance results, with additive migration 004 and persistent FIFO lot revisions.
The generated field inventory includes all these fields; unknown fields remain denied.

[Step 03](../docs/step-03-private-dashboard.md) adds optional operational `inspection_context` records and the separate `private-owner-v2.json` browser schema. The fixture builder regenerates the browser schema. `export_v2.validate_private` validates its shape, hash, cutoffs and evidence; the legacy v1 validator rejects it. Real private bundles are never reclassified into the fixture-v1 exporter.

The separate `dashboard-v1.json` schema describes sanitized read-only exports. It is
generated by `python scripts/export_dashboard_schema.py`; `trade-theorist validate
<report.json>` checks its structure, content hash and evidence references. It is
also bundled with each local dashboard export for validation before rendering.

`contracts-v1.json` is standard JSON Schema Draft 2020-12, generated from the package's declarative schema by `python scripts/export_schemas.py`. The test suite requires the two representations to match. It contains the eleven minimum contracts plus experiment, Character, portfolio, test registration, conversation and model-call records needed to resolve their references.

Every record has `id`, `record_type`, `schema_version`, `created_at`, `experiment_id` and `contamination`. IDs are stable opaque strings, independent of filenames and display titles. Message identity uses the common `id`; `recipient_character_ids` contains pinned Character-version record IDs. Source records may be global (`experiment_id: null`); experiment state and mail may not cross experiment boundaries. A copied source revision needs a new ID and provenance.

Money uses decimal strings with two places; prices use the same representation in this initial contract. Quantities, ratios expressed in basis points, and signed ledger deltas accept at most eight decimal places. Arithmetic consumers must use `Decimal`; JSON floats are prohibited for money. Confidence and weight fractions are finite numbers in [0,1]. Timestamps require explicit UTC `Z` and real calendar dates. No unknown fields, versions, enums or unsupported asset classes are accepted.

`validate(record)` checks structure and local invariants. `validate_bundle(records)` additionally resolves typed references, experiment membership, frozen policy/clock consistency, snapshot eligibility/hashes, checkpoint sequence, and preregistration timing. A standalone valid record is **not** a verified reference bundle. The store only accepts bundles whose references resolve, allowing mutually dependent experiment/Character/policy records to enter in one transaction. Instrument IDs resolve against the experiment's frozen universe; order IDs resolve to order ledger records.

`trade-theorist validate schemas/fixtures/accepted/bundle.json` validates all eighteen record types. Rejected fixtures cover publication eligibility, confidence, asset restrictions, money, clocks, paper policy and foreign experiments. `migrations/theory-v0.json` demonstrates the single supported historical field rename: `logic_chain` → `minimal_logic_chain`. Use `trade-theorist migrate-theory <old> <new>` to create a new file; v0 is never accepted directly, the original is retained, and all other version changes fail closed. No source rights or missing provenance are fabricated during migration.

The additive `learning_session` contract supplies a non-trading scope for source learning. Its ID is its own `experiment_id`; only Characters, checkpoints, model-import calls, theory/test registrations and learning manifests may reference it. Policies, market observations, portfolios, recommendations and ledger activity cannot enter. Its evidence is fixture or hindsight-contaminated, never forward performance. Source access now distinguishes `user_supplied` from an asserted owned copy; the authorization evidence must state the actual scope and cannot imply a publisher redistribution license.

The schema validates a policy document's completeness, not the authenticity of a human signature or whether a market instrument really meets declared liquidity criteria. Paper operation is a later task with independent approval and data qualification. The synthetic policy carries proposed numbers only as test data. `examples/paper-policy.template.json` and `examples/preregistration.template.json` intentionally fail validation until their unresolved fields are filled and approved.

Source citations contain source ID, actual section locator and passage hash. The learning engine also verifies short supporting quotations against the supplied private material. This proves locator/text consistency; substantive faithfulness and lawful source rights still require review. All fixture examples are original synthetic material and cannot establish real reading or investment performance.

## Declared source completion

The additive checkpoint scopes `full_paper` and `approved_excerpt` support the owner-adopted Microstructure curriculum. `reading_status: complete` means completion of the declared material scope; it is not synonymous with a full published book. Scope and excerpt authority are enforced against the pinned curriculum when learning starts. The engine requires reviewed declared coverage and exact predecessor source/scope completion. `sample` and `fixture` remain ineligible for completed reading. Existing full-book records and frozen Bogle artifacts are unchanged.
